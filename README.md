## Running a Cressida mission against this project

### ⚠️ The `cressida` command on PATH is currently broken

`C:\Users\adity\.local\bin\cressida` (also `%APPDATA%\Roaming\Python\Python313\Scripts\cressida.exe`) is a
pip-generated launcher whose shebang points at a Python interpreter inside a **stale Claude Code session
scratchpad** that no longer exists:

```
#!C:\Users\adity\AppData\Local\Temp\claude\...\scratchpad\cressida_home2\venv\Scripts\python.exe
```

Because that interpreter is gone, the exe fails immediately with exit code 1 and **no stdout/stderr at all** —
this is why `cressida run prd.md` silently did nothing. Fix it properly by reinstalling the entry point for the
system interpreter:

```bash
cd C:/Users/adity/Desktop/Cressida/cressida
python -m pip install -e ".[anthropic]"
```

This rewrites the launcher's shebang to point at `C:\Python313\python.exe` (or whichever `python` ran the
install), after which plain `cressida run ...` will work again.

### Working command today (no reinstall needed)

Until the entry point is fixed, invoke the CLI as a module with the system Python instead — this bypasses the
broken launcher entirely and works right now:

```bash
python -m cressida.cli run "C:/Users/adity/Desktop/LLMPlane/prd.md" --project-dir "C:/Users/adity/Desktop/LLMPlane"
```

Run from anywhere as long as `cressida` is importable (`pip install -e .` from the Cressida repo makes it
importable system-wide). `--project-dir` is required for the mission to write implementation code into
*this* directory — naming the path in the brief text alone is not enough.
